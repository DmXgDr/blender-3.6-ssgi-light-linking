# Windows 构建与发布

## 来源

修改后的 Blender 快照在 `blender/`；`patches/blender-3.6.2-ssgi-light-linking-r4.patch` 是相对官方 3.6.2 的完整差异，不要再叠加应用单独的 SSGI 来源补丁。来源补丁仅用于追溯与署名。

运行时使用的官方附带 Python 插件源码也已放入 `blender/scripts/addons`。字体、翻译和内置模板保留于源码/分发资源；相应原始许可证不变。

## 依赖与构建

1. 安装 Visual Studio 2022 C++ Build Tools（含 Windows SDK）、CMake、Ninja、Git。已验证 MSVC 19.44；其他版本需自行验证。
2. 获取 Blender 3.6 对应 Windows x64 依赖：`https://projects.blender.org/blender/lib-windows_x64.git`，本次使用提交 `682da7fc9d72958e75d6e9dfd11f76ddacd03081`，确保 Git LFS 大文件实际下载完成。第三方源码/构建配方见 `blender/build_files/build_environment`。
3. 打开 x64 Native Tools 命令行，在仓库根目录运行 `Build-Windows.cmd <依赖目录>`。可用第二参数指定输出根目录，默认 `build-output`。
4. 安装产物在输出根目录的 `app`；构建脚本关闭 Cycles、测试程序、缩略图安装器，打包 CRT。文件关联不自动注册。

源码快照没有原始 Git 历史，自己编译时内置 build hash 可能为 unknown；发布清单的源码修订号仍标识原始快照。编译日期、工具链和绝对路径不同，不保证自行编译的文件字节级相同。

## 制作标准配置目录包

- 不附带 `3.6/config`，不设置 BLENDER_USER_CONFIG / APPDATA 等重定向。
- 从构建生成的安装产物打包。
- 直接使用构建产物中的官方 `3.6/datafiles/colormanagement`。
- 复制 `distribution/launchers` 的启动入口；直接运行 blender.exe 也应可用。
- 排除 PDB、Python 缓存、日志与测试输出。保留许可证和上游自带示例。
- 发布前执行解压异地启动、标准配置发现/读取、链接渲染和保存重开测试。

## 编译路径处理

`tools/sanitize_build_paths.py` 只允许替换 PE 的只读、不可执行 `.rdata` 中的等长 ASCII / UTF-16LE 路径前缀，验证其余字节与所有可执行段不变。使用时传入原路径前缀和等长替换前缀。

发布 R4 原始二进制与处理后哈希、可执行段哈希记录于发布清单。功能测试针对实际最终分发文件执行。
